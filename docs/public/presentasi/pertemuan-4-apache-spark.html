⚖️ MapReduce vs Spark

Apa yang Berubah?

Spark bukan sekadar versi cepat MapReduce; ia mengubah cara job direncanakan dan dieksekusi:

AspekMapReduceSpark
Antar-faseTulis ke HDFSIn-memory / pipelining
OptimasiTerbatas, per jobCatalyst + Tungsten + AQE
APILow-level map/reduceDataFrame, SQL, streaming, ML
Iterasi MLMahal (disk I/O)Jauh lebih efisien
InteraktifTidakYa (notebook/shell)

🏗️ Arsitektur

Driver, Executor, dan Cluster Manager

Driver menyusun rencana; executor menjalankan task secara paralel:

🧠 Driver
Menjalankan main(), membuat SparkSession, menyusun DAG, menjadwalkan task, mengumpulkan hasil.
⚙️ Executor
Proses JVM di worker: menjalankan task, menyimpan cache, melaporkan status.
🎛️ Cluster Manager
Mengalokasikan resource: YARN, Kubernetes, atau Standalone.
📦 Partisi & Task
Satu task per partisi per stage; jumlah partisi menentukan paralelisme.
💡 Job dipicu satu aksi. Stage dipisahkan oleh shuffle. Task adalah unit kerja terkecil.
05 / 17
⚡ Lazy & DAG

Tidak Ada Eksekusi Sampai Ada Aksi

Spark membangun rencana logis, lalu optimizer memilih strategi terbaik:

df = spark.read.parquet("...")      # lazy
clean = df.filter(F.col("amount") > 0) # lazy
agg = clean.groupBy("city").count()    # lazy
agg.show()                             # aksi -> eksekusi
🧩 Sempit (narrow)
map, filter, select: satu partisi input → satu partisi output. Tanpa jaringan.
🌐 Lebar (wide)
groupBy, join, distinct: butuh shuffle. Di sinilah waktu dan biaya habis.

🧹 Bronze → Silver

Membersihkan & Memvalidasi

Empat aturan kualitas dasar: id tidak null, timestamp valid, amount non-negatif, event unik:

from pyspark.sql import SparkSession, functions as F

spark = (SparkSession.builder
    .appName("events-etl")
    .master("local[*]")
    .config("spark.sql.shuffle.partitions", "8")
    .config("spark.sql.adaptive.enabled", "true")
    .getOrCreate())

raw = spark.read.json("data/bronze/events")

silver = (raw
    .withColumn("event_ts", F.to_timestamp("event_ts"))
    .withColumn("dt", F.to_date("event_ts"))
    .withColumn("amount", F.col("amount").cast("double"))
    .filter(F.col("event_id").isNotNull())
    .filter(F.col("event_ts").isNotNull())
    .filter(F.col("amount") >= 0)
    .dropDuplicates(["event_id"]))

(silver.write.mode("overwrite")
       .partitionBy("dt")
       .parquet("data/silver/events"))

🥇 Silver → Gold

Join, Agregasi, dan Metrik Bisnis

Broadcast tabel kecil, lalu hasilkan agregat harian per kota:

events = spark.read.parquet("data/silver/events")
products = spark.read.parquet("data/reference/products")  # kecil

enriched = events.join(F.broadcast(products), "product_id", "left")

daily_city = (enriched
    .groupBy("dt", "city")
    .agg(
        F.count("*").alias("total_events"),
        F.countDistinct("user_id").alias("unique_users"),
        F.sum(F.when(F.col("event_type") == "payment", F.col("amount"))
               .otherwise(0)).alias("revenue"),
    )
    .withColumn("conversion_rate",
        F.round(F.col("revenue") / F.col("unique_users"), 2)))

(daily_city.write.mode("overwrite")
           .partitionBy("dt")
           .parquet("data/gold/daily_city"))

🔍 SQL & Window

Deklaratif, Terbaca, Teroptimasi

Gunakan SQL untuk agregasi; window function untuk analisis sesi dan funnel:

spark.sql('''
  SELECT dt, event_type,
         COUNT(*) AS total,
         COUNT(DISTINCT user_id) AS users
  FROM events
  WHERE dt >= DATE '2026-09-01'
  GROUP BY dt, event_type
  ORDER BY dt, total DESC
''').show(20)
from pyspark.sql import Window

w = Window.partitionBy("user_id").orderBy("event_ts")

funnel = (events
  .withColumn("prev_event", F.lag("event_type").over(w))
  .withColumn("prev_ts", F.lag("event_ts").over(w))
  .withColumn("seconds_since_prev",
      F.unix_timestamp("event_ts") - F.unix_timestamp("prev_ts")))

📊 Partisi & Shuffle

Angka yang Wajib Diperhatikan

Target ukuran partisi: 100–200 MB di memori. Default shuffle partition 200 sering terlalu banyak untuk data kecil:

OperasiEfekKapan Dipakai
repartition(n)Shuffle penuh, seimbangMenambah paralelisme
repartition(n, col)Shuffle by keySebelum join/tulis
coalesce(n)Gabung tanpa shuffle penuhKurangi file sebelum write
broadcast(df)Kirim tabel kecil ke executorJoin tabel < 10 MB
cache()Simpan di memoriDataFrame dipakai berulang

🚀 Enam Pengungkit Performa

Dari Broadcast sampai Small Files

Urutkan dari yang paling sering memberi dampak:

📡 Broadcast Join
Hindari shuffle tabel besar. Naikkan threshold hati-hati; tabel terlalu besar menyebabkan driver OOM.
🧮 AQE
Coalesce partisi kecil, ubah join strategy, tangani skew otomatis. Aktif sejak Spark 3.2.
💾 Cache Bijak
Cache hanya DataFrame yang dipakai berulang; selalu unpersist().
🐍 Hindari Python UDF
Gunakan fungsi bawaan Catalyst; jika terpaksa, pakai pandas UDF berbasis Arrow.
🧂 Skew
Salting key besar, broadcast tabel kecil, atau pisahkan outlier.
📦 Small Files
coalesce atau maxRecordsPerFile; target 128 MB–1 GB per file.

🧪 Menguji Job

Transformasi sebagai Fungsi Murni

Pisahkan logika dari I/O agar dapat diuji dengan Spark lokal:

# jobs/transforms.py
from pyspark.sql import DataFrame, functions as F

def clean_events(df: DataFrame) -> DataFrame:
    return (df
      .withColumn("event_ts", F.to_timestamp("event_ts"))
      .withColumn("dt", F.to_date("event_ts"))
      .filter(F.col("event_id").isNotNull())
      .filter(F.col("amount") >= 0)
      .dropDuplicates(["event_id"]))
# tests/test_transforms.py
def test_clean_events(spark):
    data = [
      ("e1", 10.0, "2026-09-01T10:00:00"),
      ("e1", 10.0, "2026-09-01T10:00:00"),
      ("e2", -5.0, "2026-09-01T11:00:00"),
    ]
    df = spark.createDataFrame(
        data, ["event_id", "amount", "event_ts"])
    result = clean_events(df).collect()
    assert len(result) == 1

🎮 Refleksi

Kuis Kilat 3 Menit

Jawab dulu, lalu klik untuk membuka jawaban:

❓ Mengapa lazy evaluation menguntungkan?
✅ Spark dapat mengoptimasi seluruh rencana sebelum eksekusi: predicate pushdown, column pruning, pemilihan join, dan penggabungan stage.
❓ Kapan memilih coalesce daripada repartition?
✅ Saat hanya ingin mengurangi jumlah partisi/file sebelum write dan tidak butuh distribusi ulang yang seimbang. Coalesce menghindari shuffle penuh.
❓ Apa gejala data skew di Spark?
✅ Beberapa task berjalan jauh lebih lama, stage tertahan di 99%, dan satu partisi jauh lebih besar. Cek distribusi key dan aktifkan AQE skew join.
