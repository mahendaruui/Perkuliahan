⚖️ EFISIENSI MEMORI

Stream-Based I/O vs Buffered I/O

Mengapa membaca file besar sekaligus ke dalam variabel memori (file_get_contents) sangat berisiko?

❌ Buffered I/O (file_get_contents)

Memuat seluruh isi file 500MB sekaligus ke RAM. Jika memory_limit server 128MB, PHP langsung melempar Fatal Error dan sistem mati seketika!

// ⚠️ Memakan RAM = Ukuran File (500 MB) $data = file_get_contents('transaksi_raksasa.csv'); // 💥 Fatal error: Allowed memory size exhausted!

✅ Stream-Based I/O (SplFileObject)

Membaca baris demi baris via buffer kecil (4-8 KB). File berukuran puluhan Gigabyte dapat diproses lancar dengan konsumsi RAM konstan $O(1)$.

$file = new \SplFileObject('transaksi_raksasa.csv', 'r'); while (!$file->eof()) { $baris = $file->fgets(); // ✨ RAM hanya ~2 MB }
Aturan Emas: Gunakan Buffered I/O (file_get_contents) hanya untuk file konfigurasi kecil (< 1MB). Untuk dataset, log, dan import data massal, selalu gunakan Stream I/O!
🔒 INTEGRITAS KONKURENSI

Pencegahan Race Condition dengan flock()

Mengendalikan hak akses baca dan tulis saat ratusan request pengguna datang pada milidetik yang sama.

1. LOCK_SH (Shared)

Kunci bersama untuk operasi Membaca. Banyak proses dapat membaca bersamaan, namun penulisan akan ditunda.

flock($handle, LOCK_SH); // Banyak user baca aman

2. LOCK_EX (Exclusive)

Kunci eksklusif untuk operasi Menulis. Hanya 1 proses yang boleh aktif, proses lain wajib antre.

flock($handle, LOCK_EX); // Tulis data eksklusif

3. LOCK_UN (Unlock)

Melepaskan kunci segera setelah operasi baca/tulis tuntas (biasanya di blok finally).

flock($handle, LOCK_UN); fclose($handle);
⚠️ Tanpa Penguncian Eksklusif: Operasi konkurensi akan menyebabkan file tertulis setengah (*Partial Write*), JSON menjadi korup (*Invalid Syntax*), atau data saldo rekening hilang!
🧱 STANDARD PHP LIBRARY (SPL)

Pemrosesan Berkas Berbasis Objek: SplFileObject

Mengganti fungsi prosedural kuno (fopen, fread, fclose) menjadi objek iterator yang modern.

📌 Keunggulan SplFileObject:

  • Auto Resource Cleanup: Berkas ditutup otomatis saat objek dihancurkan (*Destructor*) tanpa risiko file handle leak.
  • Iterator Bawaan: File dapat langsung di-loop dengan foreach baris per baris.
  • Flags Cerdas: Mampu otomatis mengabaikan baris kosong (SKIP_EMPTY) dan menghapus karakter newline (DROP_NEW_LINE).
  • Metadata Ekstensif: Menyediakan method getSize(), getMTime(), getExtension().
demo_spl_file.php
$file = new \SplFileObject('data/catatan.txt', 'r'); $file->setFlags( \SplFileObject::SKIP_EMPTY | \SplFileObject::DROP_NEW_LINE ); foreach ($file as $nomorBaris => $teks) { echo "Baris #{$nomorBaris}: {$teks} "; }
📊 PARSING CSV MODERN

Membaca & Menulis Berkas CSV Berbasis OOP

Mengubah data tabular CSV menjadi objek domain secara otomatis dan hemat memori.

📌 Konfigurasi Flag CSV:

Cukup aktifkan flag READ_CSV, maka setiap iterasi foreach akan otomatis menghasilkan array kolom yang sudah di-parse sesuai delimiter!

$file = new \SplFileObject('mahasiswa.csv', 'r'); $file->setFlags(\SplFileObject::READ_CSV); $file->setCsvControl(',', '"'); foreach ($file as [$npm, $nama, $prodi]) { $mhs = new Mahasiswa($npm, $nama, $prodi); }

📌 Menulis CSV dengan fputcsv():

Menyimpan array ke file CSV dengan proteksi escape karakter khusus otomatis:

$export = new \SplFileObject('laporan.csv', 'w'); $export->fputcsv(['NPM', 'Nama', 'IPK']); // Header foreach ($koleksiMahasiswa as $m) { $export->fputcsv([$m->npm, $m->nama, $m->ipk]); }
⚡ PARSING JSON & PHP 8.3+

Pengolahan JSON Aman & Fitur json_validate()

Menghilangkan silent error pada serialisasi dan memvalidasi sintaks JSON tanpa beban alokasi memori.

1. Flag JSON_THROW_ON_ERROR

Memaksa PHP melempar JsonException saat decode/encode gagal, alih-alih mengembalikan null:

try { $data = json_decode( $jsonString, associative: true, flags: JSON_THROW_ON_ERROR ); } catch (\JsonException $e) { logError("JSON Korup: " . $e->getMessage()); }

2. Fitur Baru PHP 8.3+: json_validate()

Memeriksa validitas sintaks JSON string tanpa perlu membangun struktur data array di RAM:

if (!json_validate($payloadJson)) { throw new \InvalidArgumentException("Payload bukan JSON valid!"); } // ✨ Super cepat & hemat RAM sebelum json_decode
🏛️ ARSITEKTUR BERLAPIS

Pola Desain: File-Based Repository Pattern

Memisahkan logika bisnis dari mekanisme penyimpanan berkas fisik melalui antarmuka (Interface).

📌 Mengapa Repository Pattern?

  • Decoupling: Lapisan Service/Domain tidak perlu tahu apakah data disimpan di JSON, CSV, MySQL, atau SQLite.
  • Testability: Memudahkan pembuatan Mock Repository saat unit test tanpa perlu membaca disk fisik.
  • Single Responsibility: Satu class repository hanya fokus pada urusan I/O berkas dan serialisasi.
Domain/Repository/MahasiswaRepositoryInterface.php
namespace App\Domain\Repository; use App\Domain\Model\Mahasiswa; interface MahasiswaRepositoryInterface { public function simpan(Mahasiswa $mhs): void; public function cariByNpm(string $npm): ?Mahasiswa; public function ambilSemua(): array; }
💾 REPOSITORY IMPLEMENTATION

Implementasi JsonMahasiswaRepository Aman

Menyimpan entitas ke berkas JSON dengan garansi penguncian eksklusif (LOCK_EX).

Infrastructure/Persistence/JsonMahasiswaRepository.php
public function simpan(Mahasiswa $mhs): void { $handle = fopen($this->filePath, 'c+'); // Buka untuk baca & tulis if (!flock($handle, LOCK_EX)) { throw new \RuntimeException("Gagal mengunci berkas database JSON!"); } try { $konten = stream_get_contents($handle); $data = $konten ? json_decode($konten, true, flags: JSON_THROW_ON_ERROR) : []; $data[$mhs->npm] = $mhs->toArray(); ftruncate($handle, 0); // Kosongkan isi lama rewind($handle); // Kembali ke awal file fwrite($handle, json_encode($data, JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR)); } finally { flock($handle, LOCK_UN); // ✨ Garansi lepas kunci fclose($handle); } }
📝 AUDIT LOGGING

Audit Logger Persisten & Rotasi Berkas

Merekam setiap aksi mutasi sistem ke dalam berkas log terstruktur dengan rotasi kapasitas otomatis.

📌 Strategi Rotasi Berkas Log:

Jika ukuran berkas app.log melampaui batas (misal 5 MB), sistem otomatis me-rename file lama menjadi app.log.1 dan membuat file log baru yang bersih.

  • Mencegah partisi harddisk server penuh 100%.
  • Memudahkan analisis log harian / mingguan.
Infrastructure/Logging/FileLogger.php
public function log(string $level, string $pesan): void { if (file_exists($this->logPath) && filesize($this->logPath) > 5242880) { rename($this->logPath, $this->logPath . '.' . time()); } $entry = sprintf( "[%s] [%s]: %s ", date('Y-m-d H:i:s'), strtoupper($level), $pesan ); file_put_contents($this->logPath, $entry, FILE_APPEND | LOCK_EX); }
💻 STUDI KASUS INTEGRATIF

Studi Kasus: Pipeline Import Mahasiswa

Membaca file CSV, memvalidasi dengan regex, dan menyimpannya ke Json Repository ber-lock.

Service/MahasiswaImportService.php
class MahasiswaImportService { public function __construct( private MahasiswaRepositoryInterface $repo, private FileLogger $logger ) {} public function importCsv(string $csvPath): int { $reader = new \SplFileObject($csvPath); $reader->setFlags(\SplFileObject::READ_CSV); $sukses = 0; foreach ($reader as [$npm, $nama, $prodi]) { $this->repo->simpan(new Mahasiswa($npm, $nama, $prodi)); $sukses++; } $this->logger->log('info', "Sukses import {$sukses} data."); return $sukses; } }

✨ Keunggulan Arsitektur Ini:

  • Hemat RAM: CSV 100.000 baris dibaca baris per baris secara streaming tanpa lonjakan memori.
  • Thread-Safe: Penguncian LOCK_EX memastikan data JSON tidak corrupt saat dieksekusi simultan.
  • Terdokumentasi: Audit logger mencatat waktu dan kuantitas data yang sukses di-import.
🎓 EVALUASI & PENUTUP

Rangkuman Pertemuan 12 & Kuis Reflektif

Sintesis persistensi berkas dan persiapan menuju prinsip desain arsitektur SOLID.

🔑 4 Inti Konsep Hari Ini:

  • Stream I/O: Konsumsi memori konstan $O(1)$ untuk berkas raksasa via SplFileObject.
  • File Locking: Mengunci berkas (LOCK_EX) demi mencegah Race Condition.
  • Safe JSON/CSV: Memanfaatkan JSON_THROW_ON_ERROR & json_validate().
  • Repository Pattern: Mengisolasi detail media penyimpanan dari entitas domain bisnis.
