⚖️ FILOSOFI DESAIN

Prinsip Fail-Fast vs Silent Failure

Mengapa mengembalikan kode status boolean (false / -1) sangat berbahaya bagi integritas sistem?

❌ Silent Failure (Legacy Approach)

Fungsi mengembalikan false saat error. Pemanggil kerap lalai memeriksa, menyebabkan data korup menyusup ke database.

$res = tarikSaldo(5000000); // return false // ⚠️ Pengembang lupa: if (!$res) { ... } cetakStruk(); // Tetap jalan! Saldo minus 💥

✅ Fail-Fast Principle (Modern OOP)

Segera hentikan alur abnormal seketika itu juga dan lempar (*throw*) objek Exception yang kaya informasi.

if ($nominal > $this->saldo) { throw new SaldoTidakCukupException( "Saldo Rp {$this->saldo} tidak cukup!" ); } // ✨ Alur terproteksi, tidak ada data rusak
Aturan Emas Uncle Bob: "Exceptions are preferable to returning error codes because they separate the error-handling logic from the core business logic." (Clean Code, 2008).
🌳 TAKSONOMI ENGINE

Pohon Hierarki \Throwable di PHP Modern

Seluruh error dan exception di PHP 7/8 berada di bawah payung antarmuka yang sama.

1. Class \Error

Kegagalan level Zend Engine internal. Biasanya tidak disarankan ditangkap pada alur bisnis.

  • TypeError (Tipe salah)
  • ValueError (Nilai di luar domain)
  • DivisionByZeroError
  • UnhandledMatchError

2. \LogicException

Kesalahan logika yang seharusnya dapat dicegah oleh programmer via perbaikan kode.

  • InvalidArgumentException
  • DomainException
  • OutOfRangeException
  • BadMethodCallException

3. \RuntimeException

Kesalahan lingkungan dinamis yang tidak dapat diprediksi saat compile-time.

  • PDOException (Database mati)
  • OverflowException
  • Custom Domain Exceptions (Saldo minus, kuota penuh)
💡 Tips Arsitektur: Gunakan LogicException untuk validasi kontrak internal programmer, dan gunakan RuntimeException sebagai induk seluruh Custom Business Exceptions Anda!
🧱 STRUKTUR KONTROL

Blok Kontrol try-catch-finally

Aturan urutan penangkapan dari spesifik ke umum serta garansi pembersihan resource.

📌 Prinsip Penangkapan Spesifik:

  • Urutan Wajib: Tangkap class anak yang paling spesifik di blok teratas, lalu akhiri dengan class induk (Throwable) di paling bawah.
  • Garansi finally: Blok finally pasti dieksekusi baik saat kode sukses maupun saat terjadi exception (bahkan setelah perintah return).
  • Kegunaan finally: Menutup koneksi database, melepaskan file lock (flock), dan me-release memory buffer.
app/Service/TransferService.php
try { $lock = fopen('lock.txt', 'w'); flock($lock, LOCK_EX); $rekening->transfer($tujuan, $nominal); } catch (SaldoTidakCukupException $e) { // 1. Tangkap domain error spesifik logPeringatan($e->getMessage()); } catch (\Throwable $e) { // 2. Tangkap error tak terduga logKritis($e->getMessage()); } finally { // 3. Garansi pelepasan resource flock($lock, LOCK_UN); fclose($lock); }
⚡ EFISIENSI SINTAKS

Multi-Catch & Non-Capturing Catches

Menghilangkan duplikasi blok penanganan dan menyederhanakan penangkapan error anonim.

1. Multi-Catch Syntax (Pipe |)

Menangani beberapa jenis exception yang berbeda dengan perlakuan logika pemulihan yang persis sama.

try { $client->kirimNotifikasi(); } catch (NetworkTimeoutException | SmsGatewayDownException $e) { // Tangani kedua error jaringan sekaligus $this->masukkanAntreanRetry($e); }

2. Non-Capturing Catches (PHP 8.0+)

Jika objek exception $e tidak dibaca pesannya, variabel tangkapan boleh ditiadakan secara legal.

try { $auth->verifikasiSession(); } catch (UnauthenticatedException) { // ✨ PHP 8.0+: Tidak perlu variabel $e header('Location: /login.php'); exit; }
🚀 FITUR MODERN PHP 8.0+

throw sebagai Expression

Mengubah statement menjadi ekspresi ringkas pada Null Coalescing, Match, dan Arrow Functions.

📌 Contoh 1: Null Coalescing Throw

Memvalidasi keberadaan parameter array/request dalam satu baris ekspresif:

$userId = $_GET['id'] ?? throw new InvalidArgumentException( "Parameter ID wajib disertakan!" );

📌 Contoh 2: Di Dalam Match Expression

Melempar exception langsung jika kondisi input tidak valid:

$diskon = match ($kategori) { 'VIP' => 0.20, 'MEMBER' => 0.10, 'UMUM' => 0.0, default => throw new DomainException("Kategori tidak dikenal") };
Keuntungan: Kode menjadi jauh lebih deklaratif, mengurangi blok percabangan if-else yang bertumpuk, dan menjaga integritas fail-fast sejak baris pertama fungsi.
💎 CLEAN ARCHITECTURE

Merancang Custom Domain Exceptions

Mengganti exception generik dengan nama kelas yang mewakili terminologi bisnis (Ubiquitous Language).

📌 Mengapa Custom Exception?

  • Nama Jelas & Terbaca: SaldoTidakCukupException jauh lebih informatif dibanding Exception generik.
  • Rich Context: Menyimpan state relevan (misal saldo saat ini & jumlah yang diminta) sebagai properti typed.
  • Static Factory Methods: Menyediakan pesan error standar yang konsisten di seluruh aplikasi.
app/Domain/Exception/SaldoTidakCukupException.php
<?php namespace App\Domain\Exception; class SaldoTidakCukupException extends \RuntimeException { public function __construct( public readonly float $saldoSaatIni, public readonly float $nominalTarik, string $pesan = "" ) { $pesan = $pesan ?: "Saldo Rp {$saldoSaatIni} kurang untuk tarik Rp {$nominalTarik}"; parent::__construct($pesan); } }
🔗 TRACEABILITY & DEBUGGING

Exception Chaining & Wrapping

Menjaga jejak akar penyebab error (Root Cause) tanpa membocorkan detail teknis rendah.

📌 Konsep Exception Chaining:

Ketika error infrastruktur terjadi (misal PDOException database), lapisan Service dapat membungkusnya (*wrap*) ke dalam PembayaranFailedException dengan menyertakan error asli sebagai parameter ke-3: $previous.

  • Lapisan UI menerima pesan bisnis yang ramah.
  • Log sistem tetap menyimpan seluruh jejak stack trace teknis hingga ke query SQL penyebabnya!
app/Service/PembayaranService.php
try { $this->db->exec("INSERT INTO bayar..."); } catch (\PDOException $e) { // Wrap & sertakan $e sebagai parameter $previous throw new PembayaranGagalException( "Transaksi pembayaran gagal diproses.", code: 500, previous: $e // 🔗 Rantai error tersimpan! ); }
🔒 SECURITY & MONITORING

Global Exception Handler & Keamanan Enterprise

Mencegah Information Disclosure pada lingkungan produksi sesuai standar OWASP.

⚠️ Bahaya di Lingkungan Produksi:

Menampilkan Raw Stack Trace ke layar publik dapat membocorkan password database, path direktori server, dan celah keamanan (*Vulnerability Disclosure*).

✅ Standar Solusi Enterprise:

Tangkap seluruh uncaught exception di satu pintu pusat, catat detail teknis ke berkas log aman (PSR-3), dan tampilkan halaman error 500 yang ramah.

bootstrap/error_handler.php
set_exception_handler(function (\Throwable $e) { // 1. Catat detail penuh ke file log internal server error_log("[CRITICAL] " . $e->getMessage() . " in " . $e->getFile() . ":" . $e->getLine()); // 2. Respon JSON / HTML aman tanpa detail teknis http_response_code(500); echo json_encode(['status' => 'error', 'message' => 'Terjadi gangguan sistem internal.']); });
💻 STUDI KASUS NYATA

Studi Kasus: Sistem Transaksi Rekening Bank

Integrasi complete error flow dengan Custom Exceptions berorientasi domain.

Domain: RekeningBank.php
class RekeningBank { public function __construct( private string $nomor, private float $saldo = 0.0 ) {} public function tarik(float $jumlah): void { if ($jumlah <= 0) { throw new \InvalidArgumentException("Nominal harus > 0"); } if ($jumlah > $this->saldo) { throw new SaldoTidakCukupException($this->saldo, $jumlah); } $this->saldo -= $jumlah; } }
Client Controller Execution
$rek = new RekeningBank("117-001", 1000000); try { $rek->tarik(1500000); } catch (SaldoTidakCukupException $e) { echo "❌ Gagal: " . $e->getMessage(); // Sisa saldo Rp 1.000.000, tarik Rp 1.500.000 } catch (\InvalidArgumentException $e) { echo "⚠️ Input Salah: " . $e->getMessage(); }
🎓 EVALUASI & PENUTUP

Rangkuman Pertemuan 10 & Kuis Reflektif

🔑 4 Inti Konsep Exception Handling:

  • Fail-Fast: Hentikan anomali seketika untuk mencegah kerusakan data lebih luas.
  • Pohon Throwable: Bedakan Error internal, LogicException logika koding, dan RuntimeException runtime.
  • Custom Exceptions: Komunikasikan aturan bisnis dengan class berorientasi domain.
  • Exception Chaining: Rawat jejak teknis tanpa mengorbankan keamanan data pengguna.
