BAGIAN I — MODEL MAPREDUCE

Divide and Conquer

Pecah input, proses paralel, kelompokkan berdasarkan key, lalu agregasi.

03 / 17
⚙️ Alur Job

Split → Map → Shuffle → Reduce

Prinsip utama: move compute to data, bukan memindahkan data ke komputasi.

1
Input split

File HDFS dipecah menjadi split (default seukuran blok 128 MB).

2
Map

Setiap split diproses paralel menjadi pasangan (key, value).

3
Shuffle & sort

Semua nilai dengan key sama dikelompokkan; ini fase paling mahal.

4
Reduce

Agregasi per key: sum, count, max, join, dan sebagainya.

5
Output

Hasil ditulis kembali ke HDFS dengan replikasi.

⚠️ Shuffle adalah biaya terbesar. Semua optimasi pada dasarnya mengurangi data yang melewati jaringan atau menyeimbangkan beban.

05 / 17
🧰 Tiga Alat Optimasi

Combiner, Partitioner, Join

Ketiganya menentukan seberapa banyak data yang bergerak di jaringan:

🔽 Combiner
Mini-reducer di sisi map. Aman untuk operasi komutatif & asosiatif (sum, max), tidak untuk median/rata-rata langsung.
🧭 Partitioner
Menentukan key ke reducer mana. Default hash(key) % numReducers. Kustom untuk menyebar key besar.
🔗 Reduce-side Join
Kedua dataset di-shuffle berdasarkan join key. Cocok untuk besar–besar, tetapi mahal.
📡 Map-side Join
Tabel kecil dibroadcast ke semua mapper. Jauh lebih cepat, tetapi butuh memori.

BAGIAN II — STREAMING & YARN

Menulis MapReduce Tanpa Java

07 / 17
🐍 Mapper & Reducer

Word Count dengan Python

Mapper mengeluarkan (kata, 1); reducer menjumlahkan per kata:

#!/usr/bin/env python3
# mapper.py
import re, sys

for line in sys.stdin:
    for word in re.findall(r"[a-zA-Z]+", line.lower()):
        print(f"{word}\t1")
#!/usr/bin/env python3
# reducer.py
import sys

current, total = None, 0
for line in sys.stdin:
    word, count = line.rstrip().split("\t", 1)
    count = int(count)
    if word == current:
        total += count
    else:
        if current is not None:
            print(f"{current}\t{total}")
        current, total = word, count

if current is not None:
    print(f"{current}\t{total}")

🚀 Menjalankan Job

Hadoop Streaming & Diagnostik

Uji lokal dulu, baru kirim ke cluster. Perhatikan counter shuffle:

# Uji lokal tanpa cluster
cat data/bronze/events/*.jsonl | ./mapper.py | sort | ./reducer.py | head

# Jalankan di Hadoop
hadoop jar "$HADOOP_HOME/share/hadoop/tools/lib/hadoop-streaming-3.3.6.jar" \
  -files mapper.py,reducer.py \
  -mapper "python3 mapper.py" \
  -reducer "python3 reducer.py" \
  -combiner "python3 reducer.py" \
  -input /data/input \
  -output /data/output/wordcount
💡 Cek Reduce shuffle bytes, Spilled Records, dan waktu task per reducer. Jika satu reducer jauh lebih lambat, curigai skew.

🧱 YARN

Manajemen Sumber Daya Cluster

YARN memisahkan manajemen resource dari model pemrograman:

🎛️ ResourceManager
Scheduler global: mengalokasikan resource dan menjadwalkan aplikasi.
🖥️ NodeManager
Agen per node: memantau container dan melaporkan kapasitas.
🧑‍💼 ApplicationMaster
Mengelola satu aplikasi: meminta container, memantau task.
📦 Container
Alokasi CPU + RAM tempat task berjalan.
⚠️ Jika container meminta RAM melebihi kapasitas node, aplikasi berhenti di status ACCEPTED. Cocokkan executor.memory + overhead dengan kapasitas node.

🗂️ Hive

External Table & Partisi

Gunakan external table agar DROP TABLE tidak menghapus data lake:

CREATE EXTERNAL TABLE analytics.events (
  event_id   STRING,
  user_id    STRING,
  event_type STRING,
  product_id STRING,
  city       STRING,
  amount     DOUBLE,
  event_ts   TIMESTAMP
)
PARTITIONED BY (dt DATE)
STORED AS PARQUET
LOCATION '/data/silver/events';

MSCK REPAIR TABLE analytics.events;
✅ Partition pruning: query dengan filter dt hanya membaca folder yang relevan. Ini penghematan terbesar di Hive.

📊 Query Analitik

Funnel & Agregasi

SQL yang sama dapat dijalankan di Hive, Spark SQL, atau Trino:

SELECT dt,
       event_type,
       COUNT(*)                AS total_event,
       COUNT(DISTINCT user_id) AS unique_users
FROM analytics.events
WHERE dt BETWEEN DATE '2026-09-01' AND DATE '2026-09-07'
GROUP BY dt, event_type
ORDER BY dt, total_event DESC;

SELECT
  COUNT(DISTINCT CASE WHEN event_type='view'        THEN user_id END) AS viewers,
  COUNT(DISTINCT CASE WHEN event_type='add_to_cart' THEN user_id END) AS cart_users,
  COUNT(DISTINCT CASE WHEN event_type='payment'     THEN user_id END) AS payers
FROM analytics.events
WHERE dt = DATE '2026-09-01';

⚡ Optimasi & Skew

Saat 99% Job Macet di Reduce

Satu key besar membuat satu reducer bekerja jauh lebih lama:

🔍 Gejala
Satu task reduce berjalan sangat lama; stage tertahan di 99%. Cek distribusi key dengan GROUP BY key ORDER BY count DESC.
🧂 Salting
Tambahkan suffix acak pada key besar (Jakarta-0..9), agregasi dua tahap, lalu gabungkan hasil.
📡 Broadcast Join
Untuk tabel kecil, kirim ke semua mapper sehingga tidak ada shuffle tabel besar.
⚙️ Konfigurasi
Aktifkan hive.optimize.skewjoin, gunakan Tez/Spark, dan hindari SELECT *.

🎮 Refleksi

Kuis Kilat 3 Menit

Jawab dulu, lalu klik untuk membuka jawaban:

❓ Mengapa combiner tidak boleh digunakan untuk menghitung median?
✅ Combiner hanya aman untuk operasi komutatif dan asosiatif. Median tidak dapat dihitung dari median sebagian data; diperlukan seluruh nilai.
❓ Apa perbedaan NameNode dan ResourceManager?
✅ NameNode mengelola metadata HDFS (lokasi blok). ResourceManager mengelola resource cluster (CPU/RAM) untuk aplikasi YARN.
❓ Mengapa external table lebih aman untuk data lake?
✅ DROP TABLE hanya menghapus metadata, bukan file data. Ini mencegah kehilangan data mentah secara tidak sengaja.
