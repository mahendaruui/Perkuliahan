Pilar 1: Filosofi Encapsulation

Mengikat data & fungsi ke dalam class sekaligus menyembunyikan detail internal (*Information Hiding*):

❌ TANPA ENKAPSULASI (SEMUA PUBLIC)

Data saldo terbuka bebas. Siapa pun (atau kode lain yang memiliki bug) dapat memanipulasi saldo tanpa otorisasi! 

$akun = new Rekening();
// 💥 Bahaya: Saldo diubah sembarangan
$akun->saldo = -5000000; // Saldo negatif?!
$akun->saldo = 999999999; // Hacker mengubah saldo
✅ DENGAN ENKAPSULASI (PROTECTED/PRIVATE)

Data saldo dikunci dengan private. Perubahan saldo HANYA bisa melalui method resmi yang memvalidasi PIN & limit! 

class Rekening {
    private float $saldo;
    public function tarik($pin, $nominal) {
        // Validasi PIN & kecukupan saldo
    }
}
🔑 Hak Akses Objek

Tiga Visibility Modifiers di PHP

Matriks perbandingan izin akses untuk properti dan method:

Modifier Class Sendiri Child Class (Pewarisan) Luar Class (Client Code) Kegunaan Utama
public ✅ Boleh ✅ Boleh ✅ Boleh Antarmuka luar / method interaksi utama
protected ✅ Boleh ✅ Boleh ❌ Ditolak (Error) Data untuk diwariskan ke turunan (Child)
private ✅ Boleh ❌ Ditolak (Error) ❌ Ditolak (Error) Data rahasia & helper internal class
💡 Prinsip Desain Bersih: Jadikan seluruh properti berstatus private atau protected secara default, dan hanya buka akses modifikasi melalui method publik yang tervalidasi.
🛡️ Data Integrity

Getter & Setter Ber-Validasi

Mengontrol alur pembacaan dan penulisan data agar tidak melanggar aturan logika:

class Pasien {
    private int $umur = 0;

    // Getter: Membaca nilai private
    public function getUmur(): int {
        return $this->umur;
    }

    // Setter: Mengubah nilai DENGAN validasi
    public function setUmur(int $umur): void {
        if ($umur < 0 || $umur > 130) {
            throw new \InvalidArgumentException(
                "Umur tidak masuk akal ({$umur})!"
            );
        }
        $this->umur = $umur;
    }
}
Manfaat Validasi Setter:
1. Mencegah Data Rusak: Nilai negatif, string kosong, atau format salah ditolak seketika.
2. Sentralisasi Aturan: Jika aturan bisnis berubah, cukup ubah di satu setter saja.
3. Read-Only Fleksibel: Buat method Getter tanpa membuat Setter jika properti tidak boleh diubah dari luar.
🧊 Immutability

Readonly Properties (PHP 8.1+)

Solusi elegan untuk properti yang boleh dibaca publik tapi tidak boleh diubah:

class Mahasiswa {
    public function __construct(
        // Readonly: Hanya bisa di-set saat new
        public readonly string $nim,
        public readonly string $nama,
        private float $ipk = 0.0
    ) {}
}

$mhs = new Mahasiswa("240101", "Ahmad");

// ✅ Boleh dibaca langsung (tanpa getter boilerplate)
echo $mhs->nim; 

// ❌ FATAL ERROR saat mencoba modifikasi!
$mhs->nim = "999999"; 
// Error: Cannot modify readonly property
Mengapa Readonly Begitu Populer?
• Menghilangkan Getter Boilerplate: Tidak perlu lagi menulis puluhan method getNim(), getNama().

• 100% Aman dari Modifikasi: Zend Engine secara ketat mengunci properti setelah constructor selesai dieksekusi.
📦 DTO Pattern

Readonly Classes (PHP 8.2+)

Menjadikan seluruh properti dalam class otomatis berstatus readonly:

// PHP 8.2: Seluruh properti otomatis readonly dan harus bertipe
readonly class DataPenggunaDTO
{
    public function __construct(
        public string $userId,
        public string $email,
        public string $role,
        public \DateTimeImmutable $createdAt
    ) {}
}

$user = new DataPenggunaDTO(
    userId: "USR-101",
    email: "budi@uui.ac.id",
    role: "Dosen",
    createdAt: new \DateTimeImmutable()
);

// Sangat ideal untuk Data Transfer Objects (DTO) dan Entity Immutability
🪄 Dynamic Property Access

Magic Methods __get() & __set()

Menangani pembacaan dan penulisan properti dinamis secara terkontrol:

class KamusData {
    private array $penyimpanan = [];

    // Mencegat penulisan: $obj->key = $val
    public function __set(string $key, mixed $val): void {
        $this->penyimpanan[$key] = $val;
    }

    // Mencegat pembacaan: echo $obj->key
    public function __get(string $key): mixed {
        return $this->penyimpanan[$key] ?? null;
    }
}

$kamus = new KamusData();
$kamus->temaWarna = "Gelap"; // Memicu __set()
echo $kamus->temaWarna;      // Memicu __get()
Kapan Menggunakan Magic Methods?
• ORM / Database Model (seperti Eloquent di Laravel): Membaca kolom tabel database secara dinamis.

• Property Overloading: Menyimpan atribut dinamis tanpa perlu deklarasi manual satu per satu.
💳 Praktikum Terbimbing

Studi Kasus: Dompet Digital (E-Wallet)

Penerapan enkapsulasi PIN, readonly nomor ponsel, dan proteksi saldo:

class DompetDigital {
    private float $saldo;

    public function __construct(
        public readonly string $noHp,
        private string $pin,
        float $saldoAwal = 0
    ) {
        $this->saldo = max(0, $saldoAwal);
    }

    public function getSaldo(): float {
        return $this->saldo;
    }

    public function transfer($pin, $nominal, $tujuan): bool {
        if ($this->pin !== $pin) return false;
        if ($nominal > $this->saldo) return false;
        
        $this->saldo -= $nominal;
        return true;
    }
}
Aspek Enkapsulasi Teruji:
• $pin bersifat private (tidak bisa dibaca dari luar).
• $noHp bersifat public readonly (bisa dibaca bebas, tapi mustahil dibajak/diubah).
• $saldo hanya bisa berkurang jika PIN cocok dan nominal mencukupi.
