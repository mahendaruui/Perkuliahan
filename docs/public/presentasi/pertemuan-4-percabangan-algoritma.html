💡 Titik Tolak Keberdayaan Program

Program sekuensial murni (baris per baris tanpa percabangan) seperti rekaman pita kaset: kaku, pasif, dan tidak peduli terhadap lingkungan luar.

Percabangan (Branching) adalah pintu gerbang kecerdasan buatan (Artificial Intelligence). Dengan percabangan, program mampu membaca keadaan dunia (state), menimbang parameter kondisi, dan memilih jalur tindakan optimal.

🏛️ Teorema Böhm-Jacopini (1966)

Corrado Böhm dan Giuseppe Jacopini membuktikan secara matematis bahwa seluruh algoritma yang dapat dihitung di alam semesta cukup dibangun hanya dengan 3 struktur kendali:

  • 1. Sequence (Aliran Sekuensial)
  • 2. Selection / Branching (Percabangan Logika)
  • 3. Iteration (Perulangan Loop)

🔀 TAKSONOMI PERCABANGAN

Klasifikasi Pola Struktur Percabangan

5 Pola Desain Pengambilan Keputusan dalam Rekayasa Perangkat Lunak

1. Tunggal (`if`)

Aksi dieksekusi HANYA jika kondisi `True`. Jika `False`, instruksi dilewati tanpa aksi alternatif.

2. Ganda (`if-else`)

Dua jalur diskrit saling lepas (*mutually exclusive*): Blok A jika `True`, Blok B jika `False`.

3. Majemuk (`if-elif-else`)

Rantai evaluasi kaskade bertingkat. Kondisi pertama yang lolos akan dieksekusi, sisanya dilewati.

4. Bersarang (*Nested If*)

Struktur percabangan di dalam percabangan lain, digunakan saat keputusan bergantung pada prasyarat sebelumnya (misal: Login valid → Cek Role Admin).

5. Multi-Way (`switch-case`)

Pemilihan jalur berdasarkan perbandingan nilai diskrit (integer, char, enum) dengan tabel loncat (*Jump Table*).

⚖️ PERBANDINGAN STRUKTURAL

`if-else-if` vs `switch-case`

Perbedaan karakteristik semantik, performa CPU & fleksibilitas logika

Dimensi Evaluasi Struktur `if-else-if` Cascade Struktur `switch-case` Selection
Bentuk Kondisi Ekspresi logika bebas (relasional, range, boolean, rentang angka) Hanya nilai diskrit eksak / konstanta tunggal (int, char, enum)
Mekanisme Eksekusi Pemeriksaan linear sekuensial satu demi satu dari atas ke bawah Dapat dioptimasi kompilator menjadi Jump Table (O(1))
Kesesuaian Kasus Rentang skor (misal: `nilai >= 85 && nilai <= 100`) Pilihan menu navigasi kasir (Pilih menu `1`, `2`, `3`)
Kebutuhan `break` Tidak perlu (otomatis berhenti pada blok yang cocok) Wajib (untuk mencegah eksekusi bocor ke case bawah / *fallthrough*)
⚡ EKSPRESI RINGKAS

Operator Kondisional Ternary (`? :`)

Sintaksis fungsional ekspresif untuk penugasan nilai satu baris (*Inline Decision*)

Format Standar Ternary:

kondisi ? nilai_jika_true : nilai_jika_false;

Operator Ternary adalah satu-satunya operator di bahasa C++/Java yang membutuhkan 3 operand.

Prinsip Clean Code:

Gunakan Ternary hanya untuk ekspresi sederhana. Hindari *Nested Ternary* bertingkat karena merusak keterbacaan kode (*readability*).

// 1. Gaya Konvensional if-else (6 baris):
string status;
if (nilai >= 60) {
    status = "LULUS";
} else {
    status = "REMIDIAL";
}

// 2. Gaya Elegan Ternary (1 baris):
string status = (nilai >= 60) ? "LULUS" : "REMIDIAL";

// 3. Di Python:
status = "LULUS" if nilai >= 60 else "REMIDIAL"

⚡ C++ (Structured Flow)
#include <iostream>
using namespace std;

int main() {
    double nilai;
    cout << "Nilai Akhir (0-100): "; cin >> nilai;

    char grade;
    if (nilai >= 85) grade = 'A';
    else if (nilai >= 75) grade = 'B';
    else if (nilai >= 65) grade = 'C';
    else if (nilai >= 50) grade = 'D';
    else grade = 'E';

    cout << "Grade Mutu : " << grade << "\n";
    return 0;
}
⚠️ ANOMALI & JEBAKAN LOGIKA

Jebakan Klasik Percabangan (Common Pitfalls)

Bug tersembunyi yang sering merusak alur komputasi perangkat lunak

1. Missing Break (Fallthrough)

Lupa menulis `break` pada `switch-case` akan menyebabkan program terus mengeksekusi case di bawahnya tanpa evaluasi kondisi!

2. Dangling Else Problem

Ambiguitas blok `else` pada nested-if tanpa tanda kurung kurawal `{}`. Blok `else` akan selalu menempel pada `if` terdekat!

3. Arrow Anti-Pattern

Nesting `if` terlalu dalam (> 4 tingkat) membuat kode membentuk panah mendatar dan sangat sulit diuji (*high cyclomatic complexity*).

🛡️ REKAYASA KODE BERSIH

Best Practice: Teknik *Early Return / Guard Clauses*

Mengubah sarang `nested-if` yang ruwet menjadi alur linear yang bersih dan elegan

❌ Kode Bersarang Rawan Bug (Arrow Code):
function prosesBayar(user, saldo) {
    if (user != null) {
        if (user.isActive) {
            if (saldo >= 100000) {
                // Eksekusi bayar
                return "SUKSES";
            }
        }
    }
    return "GAGAL";
}
✅ Menggunakan Guard Clause (Linear & Bersih):
function prosesBayar(user, saldo) {
    // Tangani skenario gagal di awal (Early Exit):
    if (user == null) return "GAGAL";
    if (!user.isActive) return "GAGAL";
    if (saldo < 100000) return "GAGAL";

    // Alur utama tanpa indentasi berlebih:
    // Eksekusi bayar
    return "SUKSES";
}

📌 Rangkuman Inti

  • Percabangan memungkinkan komputer bertindak adaptif dan mengambil keputusan deterministik.
  • Pilih `if-else-if` untuk evaluasi rentang nilai; gunakan `switch-case` untuk menu diskrit bernilai tetap.
  • Gunakan *Guard Clauses* untuk meratakan sarang percabangan yang rumit.
