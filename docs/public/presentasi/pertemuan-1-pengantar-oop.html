🧠 Konsep Dasar

Apa itu Paradigma Pemrograman?

Cara pandang dan pola pikir dalam menstrukturkan dan menyelesaikan masalah komputasi

PARADIGMA 1
Pemrograman Prosedural / Terstruktur

• Program dipandang sebagai urutan langkah algoritma (langkah 1, 2, 3...).
• Fokus pada fungsi / prosedur (aksi / verbs).
• Data dan fungsi terpisah — data mengalir bebas melintasi fungsi.
• Rentan terjadi efek domino ketika struktur data diubah pada proyek besar.

PARADIGMA 2
Pemrograman Berorientasi Objek (OOP)

• Program dipandang sebagai komunitas objek mandiri yang saling berinteraksi dan bertukar pesan.
• Fokus pada entitas / objek (benda nyata / nouns).
• Data dan fungsi dibungkus menjadi satu kesatuan utuh.
• Sangat modular, aman, dan mudah dikembangkan dalam skala enterprise.

⚖️ Head-to-Head Comparison

Prosedural vs Berorientasi Objek

Mengapa industri software beralih ke paradigma berorientasi objek?

Fitur / Parameter Pemrograman Prosedural (C / Pascal) Pemrograman OOP (Java / PHP / C#)
Pusat Pendekatan Fungsi, Algoritma, Alur Instruksi Objek (Data + Perilaku)
Struktur Kode Top-Down (dipecah jadi fungsi kecil) Bottom-Up (dibangun dari Class & Objek)
Keamanan Data Rendah (Data global rentan diubah fungsi lain) Tinggi (Data dilindungi lewat Encapsulation)
Code Reusability Terbatas pada pemanggilan fungsi Sangat tinggi via Inheritance & Polymorphism
Kemudahan Maintenance Sulit saat kode membesar (> 10.000 baris) Sangat rapi, modular, dan terisolasi
Pemodelan Masalah Abstraksi matematika / komputasi Memodelkan langsung entitas dunia nyata
🏛️ Fondasi Fundamental

4 Pilar Utama OOP

Empat konsep pilar penopang seluruh arsitektur berorientasi objek:

🔒
1. Encapsulation
Membungkus data (atribut) dan method serta menyembunyikan detail internal dari akses luar yang tidak sah (*Information Hiding*).
🧬
2. Inheritance
Mekanisme pewarisan sifat di mana child class dapat mewarisi dan memperluas atribut & method dari parent class tanpa menulis ulang kode.
🎭
3. Polymorphism
Kemampuan satu antarmuka (*interface*) atau method untuk memiliki banyak bentuk implementasi perilaku yang berbeda saat runtime.
🧩
4. Abstraction
Menyembunyikan kerumitan implementasi mesin dan hanya menampilkan fungsionalitas esensial kepada pengguna (*Interface / Abstract*).
🚗 Analogi Nyata

Memodelkan Objek: "Mobil"

Setiap objek memiliki 2 karakteristik utama: Atribut (State) dan Perilaku (Behavior)

📊 1. Atribut / State (Data/Variabel)
Ciri-ciri atau kondisi yang melekat pada objek:
• merk = "Toyota"
• warna = "Hitam Metalik"
• kecepatanSaatIni = 60 km/jam
• kapasitasBensin = 45 liter
⚙️ 2. Method / Behavior (Fungsi/Aksi)
Tindakan atau operasi yang bisa dilakukan objek:
• tambahKecepatan(int gas)
• rem()
• isiBensin(double liter)
• klakson() 
// Representasi Class Objek di Java
public class Mobil {
    // 1. Atribut Private (Encapsulation)
    private String merk;
    private int kecepatan = 0;

    // 2. Constructor Inisialisasi
    public Mobil(String merk) {
        this.merk = merk;
    }

    // 3. Method Perilaku
    public void gas(int tambah) {
        this.kecepatan += tambah;
        System.out.println(merk + " melaju: " + kecepatan + " km/j");
    }
}
🚀 Nilai Tambah Industri

Mengapa Belajar OOP Sangat Krusial?

Alasan utama seluruh framework modern dibangun di atas paradigma OOP:

🧱
Modularitas Tinggi
Kode terpisah ke dalam class mandiri sehingga bug pada satu modul tidak merusak modul lainnya.
🔄
Prinsip DRY
Don't Repeat Yourself — Menghemat ribuan baris kode melalui mekanisme pewarisan (Inheritance).
🛡️
Integritas & Keamanan
Data kritis terlindungi dari manipulasi langsung berkat kontrol visibilitas private dan validasi setter.
📈
Skalabilitas Enterprise
Mempermudah ratusan software engineer bekerja bersama dalam satu basis kode aplikasi skala besar.
⚡
Fondasi Framework Modern
Prasyarat mutlak memahami Spring Boot, Laravel, NestJS, Flutter, .NET, dan Android Development.
🧪
Kemudahan Testing
Objek terenkapsulasi sangat mudah diuji secara otomatis menggunakan Unit Test (JUnit, PHPUnit).
