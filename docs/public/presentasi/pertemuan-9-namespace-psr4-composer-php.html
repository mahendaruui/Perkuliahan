⚠️ MASALAH PERANGKAT LUNAK

Tantangan: Name Collision pada Proyek Skala Besar

Apa yang terjadi ketika dua pustaka berbeda mendefinisikan nama class yang sama persis?

❌ Tanpa Namespace (Global Scope)

Semua class berada dalam satu ruang global. Jika Anda mengimpor library pembayaran dan akuntansi:

error_fatal.php
// Pustaka Gateway Pembayaran class Transaction { ... } // Pustaka Laporan Akuntansi class Transaction { ... } // 💥 Fatal error: Cannot declare class Transaction, // because the name is already in use!

✅ Solusi: Namespace Isolation

Mengelompokkan kode ke dalam ruang nama virtual (seperti folder virtual di dalam memori):

solusi_terisolasi.php
namespace Payment\Gateway; class Transaction { ... } namespace Accounting\Report; class Transaction { ... } // ✨ Keduanya hidup berdampingan secara damai!
Analogi Dunia Nyata: Dua mahasiswa bernama "Budi". Tanpa identitas jurusan (namespace), kampus akan bingung. Namun dengan Informatika\Budi dan Kedokteran\Budi, identitas objek menjadi sangat presisi!
🛠️ IMPLEMENTASI SINTAKS

Deklarasi Namespace di PHP 8+

Aturan resmi penulisan ruang nama dan hierarki bertingkat.

📌 Aturan Penting Namespace:

  • Baris Pertama: Deklarasi namespace wajib ditulis di baris pertama file PHP (tepat setelah tag <?php).
  • Simbol Backslash (\): Digunakan sebagai pemisah tingkatan sub-namespace (bukan garis miring atau titik).
  • Konvensi Penamaan: Menggunakan PascalCase untuk setiap segmen: VendorName\PackageName\SubNamespace.
Struktur Hierarkis Standar:
App\Domain\Model (Entitas Data)
App\Service\Payment (Logika Bisnis)
App\Infrastructure\Database (Akses Penyimpanan)
src/Domain/Model/Mahasiswa.php
<?php declare(strict_types=1); namespace App\Domain\Model; class Mahasiswa { public function __construct( public readonly string $npm, public readonly string $nama, public float $ipk = 0.0 ) {} public function getRingkasan(): string { return "[{$this->npm}] {$this->nama} (IPK: {$this->ipk})"; } }
🔍 TEORI RESOLUSI NAMA

Tiga Model Resolusi Nama di PHP

Bagaimana PHP Compiler / Zend Engine mencari dan memetakan class yang dipanggil?

1. Unqualified Name

Pemanggilan nama class tunggal tanpa ada backslash pemisah.

$mhs = new Mahasiswa(); // Dicari di namespace lokal saat ini.

Analogi file: file.txt (direktori saat ini).

2. Qualified Name

Pemanggilan bersegmen dengan backslash di tengah, tanpa backslash awal.

$mhs = new Model\Mahasiswa(); // Relatif terhadap namespace aktif.

Analogi file: subfolder/file.txt.

3. Fully Qualified (FQN)

Pemanggilan absolut diawali backslash \ dari akar root namespace.

$mhs = new \App\Domain\Model\Mahasiswa(); // Pasti tepat & tidak ambigu.

Analogi file: /var/www/file.txt.

⚠️ Perhatian untuk Built-in Global Classes: Saat berada di dalam namespace, class global PHP (seperti DateTime, Exception, PDO) wajib diawali backslash (e.g., new \DateTime()) atau di-import menggunakan use DateTime;.
✨ SINTAKS MODERN

Import & Aliasing Menggunakan use & as

Menulis kode ringkas, elegan, dan bebas benturan antar pustaka.

📌 Fitur Pernyataan use

  • Class Import: Mengimpor FQN sekali di atas berkas sehingga kode pemanggilan menjadi singkat (new Mahasiswa alih-alih FQN panjang).
  • Aliasing dengan as: Mengganti nama alias ketika dua library memiliki nama class yang identik.
  • Group Use Syntax: Mengimpor beberapa class dari sub-namespace yang sama dalam satu baris (PHP 7+ / 8+).
app/Controller/KrsController.php
<?php namespace App\Controller; // 1. Import class tunggal use App\Domain\Model\Mahasiswa; // 2. Aliasing untuk mengatasi nama kembar use Payment\Invoice as PaymentInvoice; use Accounting\Invoice as ReportInvoice; // 3. Group use syntax use App\Service\{KrsService, PaymentService, NotificationService}; class KrsController { public function proses(): void { $inv = new PaymentInvoice(); // Jelas & aman } }
⚡ EVOLUSI SISTEM

Evolusi Autoloading: Selamat Tinggal "Include Hell"

Bagaimana PHP bertransformasi dari pemuatan manual yang rapuh menuju Lazy Loading otomatis.

❌ Era Tradisional (Include Hell)

require_once 'Domain/Mahasiswa.php'; require_once 'Domain/MataKuliah.php'; require_once 'Domain/Dosen.php'; require_once 'Service/KrsService.php'; require_once 'Repository/KrsRepository.php'; // ❌ Lambat, membebani RAM, rawan lupa!

Setiap penambahan class baru memerlukan puluhan baris import manual di setiap file script.

✅ Era Modern: spl_autoload_register()

spl_autoload_register(function (string $class) { $file = __DIR__ . '/src/' . str_replace('\\', '/', $class) . '.php'; if (file_exists($file)) { require_once $file; } });

Lazy Loading: Berkas PHP hanya dimuat ke memori saat class tersebut pertama kali dibuat objeknya dengan new.

📐 STANDAR INDUSTRI (PHP-FIG)

Standar Autoloading PSR-4

Aturan pemetaan matematis antara Namespace terstruktur dengan direktori berkas fisik di server.

Formula Pemetaan PSR-4:

\<NamespacePrefix>\<SubNamespace>\<ClassName> → <base_directory>/<SubNamespace>/<ClassName>.php

📌 Contoh Pemetaan Konkrit:

  • Namespace Prefix: App\
  • Base Directory: src/
  • Nama Class FQN: App\Domain\Model\Mahasiswa
  • Lokasi File Fisik: src/Domain/Model/Mahasiswa.php

⚠️ Ketentuan Wajib PSR-4:

  • Nama class dan file wajib persis sama termasuk huruf besar-kecilnya (Case-Sensitive).
  • Ekstensi berkas harus .php.
  • Setiap sub-namespace mencerminkan sub-folder direktori secara presisi 1-ke-1.
📦 PACKAGE & DEPENDENCY MANAGER

Composer: Jantung Ekosistem PHP Modern

Manajemen dependensi resmi untuk mengunduh pustaka dan mengotomasi PSR-4.

🚀 Perintah Dasar Composer:

  • composer init : Menginisialisasi proyek baru dan menghasilkan file konfigurasi.
  • composer require <vendor/paket> : Mengunduh dan menginstal pustaka eksternal (e.g. Monolog, PHPUnit).
  • composer install : Menginstal dependensi berdasarkan composer.lock.
  • composer dump-autoload : Menyusun ulang peta autoloader kelas.
composer.json
{ "name": "uui/sistem-krs", "description": "Aplikasi Manajemen KRS Berbasis OOP PHP 8+", "type": "project", "require": { "php": "^8.1" }, "autoload": { "psr-4": { "App\\": "src/" } } }
⚡ HIGH PERFORMANCE

Optimasi Autoloader untuk Lingkungan Produksi

Meningkatkan kecepatan respon aplikasi hingga 40% dengan Classmap Caching.

🛠️ Mode Development (Bawaan)

Setiap ada pemanggilan class baru, Composer memeriksa keberadaan file di harddisk secara dinamis melalui stat filesystem call.

$ composer dump-autoload // Fleksibel untuk edit kode harian, namun // menghasilkan latensi disk I/O di server.

🚀 Mode Production (Optimized Classmap)

Composer memindai seluruh folder proyek sekali dan membuat kamus Array statis (Hash Map) di memori RAM.

$ composer dump-autoload -o # atau saat deploy: $ composer install --no-dev --optimize-autoloader
Hasil Optimasi: Kompleksitas pencarian file class berubah dari O(N) disk scan menjadi O(1) in-memory hash table lookup. Sangat krusial untuk server web dengan trafik tinggi!
