📋 Agenda Pembahasan Perkuliahan

💡 Kompetensi Rekayasa Arsitektur

Setelah materi ini, mahasiswa meninggalkan pola koding monolitik spaghetti:

  • Logika bisnis terisolasi murni dan dapat diuji (Unit Tested) tanpa database.
  • Ganti media penyimpanan (misal JSON ke MySQL/PostgreSQL) cukup buat 1 class baru.
  • Struktur folder terstandar PSR-4 yang digunakan di framework modern (Laravel/Symfony).
⚠️ MASALAH ARSITEKTUR

Bahaya Aplikasi Tanpa Arsitektur Berlapis

Mengapa menaruh semua logika bisnis dan query database di dalam file Controller sangat merusak?

❌ The Spaghetti Controller Antipattern

  • Tergantung Server Web: Logika tidak bisa dijalankan di CLI cron job tanpa menduplikasi kode.
  • Tergantung Database Spesifik: SQL query tertanam di puluhan controller. Jika pindah database, seluruh aplikasi harus ditulis ulang!
  • Mustahil Diuji (Untestable): Pengujian menuntut koneksi HTTP dan database aktif setiap saat.

✅ Clean Architecture Solution

  • Domain Independence: Inti bisnis tidak mengenal database, web framework, atau UI.
  • Pluggable Infrastructure: Database, API eksternal, dan UI hanyalah "plugin" di lapisan terluar.
  • Testability: 100% alur bisnis dapat diuji secara instan dengan Mock Repository di memori.
Prinsip Inti Robert C. Martin: "A good architecture allows major decisions to be deferred! The database is a detail, the web is a detail." (Clean Architecture, 2017).
🎯 ATURAN KETERGANTUNGAN

4 Lapisan Konsentris & The Dependency Rule

Dependensi kode sumber hanya boleh menunjuk ke arah DALAM (Lapisan Luar → Lapisan Dalam).

📌 Hierarki 4 Lapisan Konsentris:

  • 1. Entities (Inti): Aturan bisnis domain murni (Class Buku, Enum StatusPinjam).
  • 2. Use Cases / Services: Alur orkestrator aplikasi (PerpustakaanService).
  • 3. Interface Adapters: Jembatan penerjemah data (JsonBukuRepository, AppController).
  • 4. Frameworks & Drivers (Luar): File JSON, Terminal CLI, PDO MySQL, HTTP Request.

🔒 Aturan Ketergantungan Mutlak:

Lapisan Entity dan Service sama sekali TIDAK BOLEH mengetahui keberadaan class dari lapisan luar (tidak boleh ada use PDO atau use JsonFile di dalam folder Domain!).

Lapisan dalam hanya mengenal Interface Kontrak miliknya sendiri!
1️⃣ LAPISAN 1: INTI DOMAIN

Lapisan 1: Entity & Value Objects

Merepresentasikan data bisnis murni dan menjaga integritas aturan invariant.

Domain/Model/StatusPinjam.php
namespace App\Domain\Model; enum StatusPinjam: string { case Tersedia = tersedia; case Dipinjam = dipinjam; case Rusak = rusak; }
Domain/Model/Buku.php
class Buku { public function __construct( public readonly string $isbn, public readonly string $judul, public readonly string $penulis, private StatusPinjam $status = StatusPinjam::Tersedia ) {} public function pinjam(): void { if ($this->status !== StatusPinjam::Tersedia) { throw new BukuTidakTersediaException("Buku sedang {$this->status->value}"); } $this->status = StatusPinjam::Dipinjam; } }
2️⃣ LAPISAN 2: KONTRAK ABSTRAKSI

Lapisan 2: Repository Contract Interface

Kontrak antarmuka di dalam domain yang mendikte operasi data tanpa peduli media penyimpanan.

📌 Mengapa Kontrak Ada di Domain?

  • Inversi Kontrol: Lapisan Domain yang menentukan apa yang ia butuhkan dari database, bukan database yang mengatur domain.
  • Type-Safe Return: Method mengembalikan objek Entity bertipe kuat (Buku atau null), bukan array liar tanpa skema.
Domain/Repository/BukuRepositoryInterface.php
<?php namespace App\Domain\Repository; use App\Domain\Model\Buku; interface BukuRepositoryInterface { public function simpan(Buku $buku): void; public function cariByIsbn(string $isbn): ?Buku; public function ambilSemua(): array; public function hapus(string $isbn): bool; }
3️⃣ LAPISAN 3: USE CASES & SERVICE

Lapisan 3: Service / Use Case Layer

Orkestrator aturan bisnis yang memandu transaksi peminjaman, validasi, dan persistensi.

Application/Service/PerpustakaanService.php
<?php namespace App\Application\Service; use App\Domain\Repository\BukuRepositoryInterface; use App\Domain\Exception\BukuNotFoundException; class PerpustakaanService { public function __construct( private readonly BukuRepositoryInterface $repo ) {} public function pinjamBuku(string $isbn, string $namaPeminjam): Buku { $buku = $this->repo->cariByIsbn($isbn) ?? throw new BukuNotFoundException("Buku dengan ISBN {$isbn} tidak ditemukan!"); $buku->pinjam(); // Mutasi state pada Entity murni $this->repo->simpan($buku); // Persistensi via Interface return $buku; } }
4️⃣ LAPISAN 4: INFRASTRUKTUR

Lapisan 4: Concrete Repository (JSON)

Mengimplementasikan kontrak interface menggunakan media berkas JSON terkunci (LOCK_EX).

📌 Peran Lapisan Infrastruktur:

  • Mengubah format mentah disk/database (JSON string) menjadi objek Domain (Buku).
  • Mengubah objek Domain menjadi struktur yang siap disimpan ke disk.
  • Mengamankan operasi file locking flock() agar aman dari konkurensi.
Infrastructure/Persistence/JsonBukuRepository.php
class JsonBukuRepository implements BukuRepositoryInterface { public function cariByIsbn(string $isbn): ?Buku { $semua = $this->ambilSemua(); return $semua[$isbn] ?? null; } public function simpan(Buku $buku): void { // Buka file, flock(LOCK_EX), tulis JSON, unlock } }
🖥️ LAPISAN 4: PRESENTASI

Lapisan 4: Presentation / Controller Layer

Menerima interaksi pengguna (CLI Console), memanggil Service, dan menampilkan output.

Presentation/Console/ConsoleAppController.php
class ConsoleAppController { public function __construct( private readonly PerpustakaanService $service ) {} public function handlePinjam(): void { $isbn = readline("Masukkan ISBN Buku: "); $nama = readline("Nama Peminjam: "); try { $buku = $this->service->pinjamBuku($isbn, $nama); echo "✅ Berhasil meminjam: {$buku->judul}\n"; } catch (PerpustakaanException $e) { echo "❌ Gagal: " . $e->getMessage() . "\n"; } } }
🔌 COMPOSITION ROOT

Inisialisasi Aplikasi (Wiring Dependencies)

Satu-satunya titik di mana dependensi konkrit dirakit dan disuntikkan ke dalam sistem.

bin/app.php (Single Entry Point)
<?php require_once __DIR__ . /../vendor/autoload.php; use App\Infrastructure\Persistence\JsonBukuRepository; use App\Application\Service\PerpustakaanService; use App\Presentation\Console\ConsoleAppController; // 1. Buat Implementasi Infrastruktur $repo = new JsonBukuRepository(__DIR__ . /../data/buku.json); // 2. Suntikkan ke Application Service $service = new PerpustakaanService($repo); // 3. Suntikkan ke Presentation Controller $app = new ConsoleAppController($service); // 4. Jalankan Aplikasi $app->run();
📂 ARSITEKTUR STRUKTUR DIREKTORI

Peta Direktori Terstandar PSR-4

Struktur proyek terorganisir yang memisahkan tanggung jawab setiap layer secara fisik.

Struktur Folder Aplikasi
my-library-app/ ├── bin/ │ └── app.php # Entry point CLI ├── data/ │ └── buku.json # Database berkas ├── src/ │ ├── Domain/ # Lapisan 1 (Inti) │ │ ├── Model/ (Buku.php) │ │ ├── Repository/ (BukuRepoInterface.php) │ │ └── Exception/ │ ├── Application/ # Lapisan 2 (Use Case) │ │ └── Service/ (PerpustakaanService.php) │ ├── Infrastructure/ # Lapisan 3-4 (Storage) │ │ └── Persistence/ (JsonBukuRepository.php) │ └── Presentation/ # Lapisan 4 (UI/CLI) │ └── Console/ (ConsoleAppController.php) ├── composer.json └── vendor/

✨ Keuntungan Struktur Ini:

  • Standar Industri: Format arsitektur yang sama persis dengan Domain-Driven Design (DDD) & Clean Architecture di enterprise.
  • Autoloading PSR-4 Otomatis: Cukup namespace App\ yang dipetakan ke folder src/.
  • Zero Coupling: Pergantian infrastruktur storage tidak akan pernah menyentuh folder src/Domain/!
